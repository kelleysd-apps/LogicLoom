# SINGLE SOURCE OF TRUTH for the "harness-dev artifact" concern. Consumed by:
#   - strip-harness-dev.sh   (REMOVES / stubs these paths when building a
#                             sanitized snapshot from a dev-main checkout)
#   - leak-guard.sh          (ASSERTS these paths are ABSENT from the snapshot;
#                             exit 1 on any leak)
#   - sanitization-audit.sh  (Check 7 delegates to leak-guard.sh, but only when
#                             this manifest + leak-guard.sh are present)
#
# TOPOLOGY (decided 2026-06-15): the customer template `main` is PUBLIC, so
# dev-main lives in a SEPARATE PRIVATE repo and this manifest + the whole release
# plumbing are themselves harness-dev — they are STRIPPED so they never ship to
# customers. The promotion build runs in the private repo; only single-parent
# sanitized snapshots are pushed to the public template.
#
# This is ORTHOGONAL to sanitize-for-template.sh (per-PROJECT generated artifacts)
# and to sanitization-audit.sh Checks 1-6 (assert the ORIGINAL ioun-ai project +
# absolute /workspaces paths were scrubbed). This manifest covers OUR harness-
# development record.
#
# TRACKED-CONTENT MODEL: the stripper and leak-guard operate on GIT-TRACKED
# content (`git ls-files`), NOT the working-tree filesystem. Gitignored runtime
# state (memory tiers' working/recall/archival contents, .logic-loom/logs,
# .loom-worktree-env, egg-info) is never tracked, so it never enters a CI
# checkout and needs no strip entry — only its tracked `.gitkeep` survives.
#
# Grammar (one entry per line; `#` begins a comment):
#   <path-or-glob>     -> REMOVED by stripper; asserted ABSENT by leak-guard
#   stub: <path> :: <template>
#                      -> CONTENT-REPLACED with <template> (a repo-relative path,
#                         conventionally under .logic-loom/templates/); asserted
#                         to carry NO harness-dev markers (not absent).
#                         The `:: <template>` field is REQUIRED and there is NO
#                         default: the stripper ABORTS on a `stub:` entry with no
#                         template, or whose template file is missing. Shipping
#                         the WRONG stub is worse than failing the release, and a
#                         default is exactly how the wrong stub gets shipped
#                         silently (the stripper used to hardcode the VISION stub
#                         for every `stub:` target).
#   warn: <path-glob>  -> NOT stripped; leak-guard emits a WARNING (non-fatal).
#                         Use for deferred decisions so nothing silently ships.
# Globs are matched against `git ls-files` output (tracked paths only).
# =============================================================================

# --- Adopt-package build tooling (maintainer-only; produces the payload, is
#     never part of it) ---
#     packaging/adopt/ is where the npm adopt package that INSTALLS LogicLoom
#     into someone else's repo is built. It is our publish machinery — package
#     manifest, installer, its own tests, the trusted-publisher wiring — and a
#     customer who cloned the template has no use for a tool that installs the
#     thing they already have. Worse, shipping it would put a second, divergent
#     copy of the installer inside every clone, which is the source-of-truth
#     failure this manifest exists to prevent.
#     WHOLESALE, and deliberately not `packaging/adopt/*` or a file list: the
#     directory does not exist yet, and the point of the wholesale form is that
#     it covers the files before anyone writes them. This is the same reasoning
#     the `.brain/memory` entry above records — an entry that matches nothing is
#     free, and a maintainer tool reaching a customer is not. strip_entry()
#     matches manifest globs against `git ls-files`, so until the directory is
#     tracked this line strips nothing and prints nothing; the day it lands, it
#     is already covered, with no release-day edit to remember.
#     `packaging` rather than `packaging/adopt` on purpose: a sibling
#     packaging/<other>/ would otherwise ship verbatim. If a customer-facing
#     thing ever needs to live under packaging/, narrow this line THEN, with the
#     reason written here.
packaging
