**1. Orchestrator + worker ladder** (`.docs/architecture/orchestrator-worker-ladder.md`). Orchestrator = model-agnostic-but-frontier ROLE targeting the `frontier` tier, set via `/model claude-fable-5` (default) with one-line downgrade to `claude-opus-4-8` (`FRONTIER_MODEL` / `FRONTIER_FALLBACK` in `models.conf`).

> **⚠️ CORRECTED 2026-07-09 — `FRONTIER_FALLBACK` is a fiction twice over.** (a) Nothing parses `models.conf` (no runtime resolver — known). (b) **Claude Code does NOT auto-fall-back on credit/usage exhaustion.** Its `fallbackModel` chain (settings array, max 3; or `--fallback-model`) fires ONLY on *overload / unavailable / non-retryable server error*. Docs explicitly exclude it: *"Authentication, **billing**, **rate-limit**, request-size, and transport errors never trigger a switch."* So a Fable-5 session **errors and stops** on credit exhaustion; recovery is a manual `/model claude-opus-4-8`. `opusplan` is a plan→execution switch, not a limit response.
> **FIX (native, actionable):** put `"fallbackModel": ["claude-opus-4-8"]` in `.claude/settings.json` — core layer, travels to every surface, makes the *overload/unavailable* fallback real. Credit exhaustion remains a hard stop; surface that honestly in `/governance-health`.
> **Quirk:** Fable 5 also has a *content-based* fallback via safety classifiers on **cybersecurity/biology** content — so the orchestrator model can silently change mid-session during LogicLoom's own security-domain work.
> Source: `code.claude.com/docs/en/model-config.md` (§ Fallback model chains / Automatic model fallback).
