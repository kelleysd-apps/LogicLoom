The floor is root-wired, but three of its eight scripts live inside a package

Every guard is wired from the root settings file — that part holds, and it is what makes the floor undisableable. But the three governance guards physically live in the loom-governance package directory while being wired from root. The wiring is anchored; the housing is not. Shown as dashed red edges crossing from the floor into the package.

It works today because the files ship in the repository regardless of whether the package is enabled. It is worth knowing that "root-anchored" describes the wiring, not where the code sits.

The plugin hook manifests use an undocumented shape — verified, and likely inert

Both loom-governance and loom-orchestrator declare hooks as a flat list of {event, matcher:{tool_name}, command}. Confirmed against the docs: the canonical plugin-hooks shape is an object keyed by event name holding {matcher, hooks:[{type, command}]} — the same shape the root settings file uses and that demonstrably fires. The flat-list form is documented nowhere.

So the plugin manifests are almost certainly inert, and the floor holds only because root wires the same three governance scripts directly. The floor is unaffected. Two live consequences remain: the file can't simply be removed — a contract test asserts its existence and another reads the flat shape — so reconciling it is a cross-cutting change, not a cleanup. And the same shape in loom-orchestrator means its Stop and SubagentStop hooks may be silently not firing — a real bug to check when we reach that layer.

What the shape tells you

One package holds nearly half the surface: the orchestrator carries 9 of 19 commands and 11 of 30 skills. Three packages depend on nothing — governance, memory, and the preflight hook — and the other five all point at governance alone. It is a star, not a web, which is what makes per-package updates tractable.

Two packages ship no commands at all: memory and the preflight hook are ambient. And the model ladder is only two files — the orchestrator is the session you are in, not an agent.
